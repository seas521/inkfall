# Inkfall 电影化角色标准

## 当前批准方向

默认新角色方向为“歪塔巨盔骑士”：

- 头盔约占总高度 `60%–65%`，小筒形身体、短挂臂与小脚只作为头盔下方的动作载体。
- 必须是明确侧面形象；歪斜平顶、顶部方形缺口、阶梯式前脸和不等长护颊是第一识别点。
- 头盔是一只完整外壳，不依靠颜色分块、材质高光或分离零件建立特色。
- 身体和头盔均保持纯黑，仅通过负空间区分手臂、身体和双脚。
- 闪电状面部开口中的前倾琥珀眼与歪嘴负责表情，气质应机灵、倔强，不是乖巧微笑。
- 可爱来自极端头身比与略笨拙的动作；帅气来自不对称轮廓、稳定重心和利落装备姿态。
- 不沿用旧角色的尖帽、南瓜、紫色服装、星光粒子或人物比例。

旧角色必须作为 `legacy` 风格保留，不覆盖其资源。

## 色彩与自发光

- 角色本体与头盔使用单一近黑色，不绘制灰色甲面、锈迹或内部材质高光。
- 角色自带光集中在头部后方，使用低透明度琥珀雾晕。
- 单只琥珀眼睛与更暗的歪嘴是角色唯一稳定亮点。
- 身体禁止全身光环、白色描边和均匀边缘光。
- 环境灯只负责衬亮角色背后的空气，不改变角色纯黑填充。

## 画面比例

以脚底为局部原点：

- 整体视觉高度约 `62–72 px`。
- 巨盔宽度明显超过小身体，身体宽度约为头盔的 `40%–48%`。
- 双腿几乎隐藏，只保留两个可区分的小脚轮廓。
- 手臂、腰部和双腿之间必须保留可读的背景负空间。
- 装备可突破碰撞宽度，但落脚点必须和碰撞体脚底一致。

## 统一姿态数据

关卡只输出语义，不直接选择动画帧。使用：

- `style_id`: `legacy`, `velvet_doll`, `pumpkin_shadow` 或当前默认 `crooked_tower`
- `feet`, `velocity`, `grounded`, `facing`
- `equipment`: `none`, `throwable`, `shield`, `blade`
- `action`: 当前语义动作
- `action_progress`: `0–1`
- `aim_angle`: 投掷或工具方向
- `effort`: 蓄力、格挡或推动力度
- `impact`: 受击反馈
- `light_exposure`: 当前环境曝光
- `combo_index`: 后续剑技变体

姿态优先级固定为：

1. 失败与重击
2. 盾牌受击、盾反、挥砍、投掷
3. 推动物体和持物
4. 起跳、上升、滞空、下落、落地
5. 起步、移动、停止、转身
6. 待机与待机小动作

高优先级动作可以覆盖上半身，但除非玩法锁定移动，不应冻结脚步相位。

## 逐帧动画原则

- 当前默认角色必须使用独立矢量 SVG 帧，不在运行时旋转独立四肢，也不从共享图集裁切。
- 使用 pose-to-pose 流程：先确定关键姿势，再添加 breakdown 和 in-between。
- 待机、起步、跑步、停止、转身、起跳、上升、顶点、下落、落地和每类交互分别保存为独立 SVG 动画目录。
- 跑步循环至少 `12` 帧，播放基准为 `18–22 fps`。
- 交互动作通常使用 `6–12` 帧，按照语义动作进度选择帧。
- 所有帧使用 `192 × 192` 完整透明画布与固定脚底根节点 `(96, 174)`；禁止 trim。
- 外轮廓、武器和动作极值必须留在安全边距内，不能贴近 SVG viewBox 边缘。
- 跑步帧按照实际水平移动距离推进，避免帧率变化和脚底滑动。
- Godot 使用 `SpriteFrames` 逐张加载 SVG，不使用 `hframes`、region 裁剪、绿幕或 atlas UV。
- 每帧自身包含完整角色和装备；动作切换时不叠加上一帧。
- 角色朝右绘制，朝左只镜像整张 Sprite，不能显示正脸。
- 轮廓必须在每一帧中作为完整黑色形体读取，禁止出现可见的球形关节或分离肢体。

### Seedance 视频抽帧规则

- 所有 Seedance 动作视频统一按照 `24 fps` 连续逐帧提取候选动作区间，禁止隔帧抽取、只选关键帧或用稀疏采样结果直接接入游戏。
- 允许先用稀疏时间轴总览定位动作起止点，但总览只能用于导航；动作质量、衔接、循环点和角色一致性必须基于完整连续帧复核。
- 最终裁剪只能删除动作开始前和结束后的连续无关区间，不能删除动作内部的过渡帧；需要调整速度时保留全部源帧，只修改播放时长。
- 同一源视频拆出的连续动作片段必须共用固定缩放、固定水平根节点和固定地面基线；禁止每段按自身包围盒重新缩放，也禁止逐帧重新居中。
- 循环动作必须在完整连续帧中查找重复步态姿势，并记录一个资源序列实际包含的步态周期数，按周期数配置对应移动距离。
- 接入前必须生成基于全部连续帧的动态预览，并检查脚底根节点、头盔轮廓、眼睛数量、装备连续性、绿幕边缘、残影和相邻帧跳变。
- 接入前必须逐帧扫描透明画布边界；任一有效像素距离四边不得小于 `3 px`，发现贴边时必须回到源视频重新取景，禁止仅把已经裁断的 PNG 向内平移。

## 基础动作

### 待机

- 通过不同整帧实现轻微呼吸和歪头，不实时扭动身体部件。
- 每隔数秒出现一次轻微歪头或观察动作。
- 琥珀头光呼吸幅度低于 `8%`。

### 移动

- 双腿连续交替，身体上下幅度小于脚步幅度。
- 手臂反相摆动，身体保持明确侧面。
- 快速移动时小身体前倾，巨盔略晚半拍跟随，但不能像独立物体脱离身体。

### 跳跃

- 起跳不延迟物理响应：使用瞬时伸展表达蹬地。
- 上升时身体伸长、脚向后收；顶点时短暂展开；下落时靴子向落点准备。
- 落地包含压缩、停顿、恢复三段，持续约 `0.12–0.18 s`。

### 受击与失败

- 普通受击以后仰、脚步停顿和头光抖动表达。
- 失败动作下沉、倾倒并渐隐，不突然切换消失帧。

## 物品与战斗动作

### 轻物体

- 拾取：观察、屈身、双手接触、起身。
- 携带：物体位于胸前，移动时手臂稳定、身体保留步态。
- 蓄力投掷：身体后移、前手瞄准、后手支撑，力度通过重心而非发光条表现。
- 释放：手臂领先、躯干跟随，随后回到稳定侧面。
- 轻放：屈身后脱手，不能复用投掷动作。

### 盾牌

- 装备、低位携带、抬盾、持续格挡、放下、短盾反、轻格挡反馈、重冲击反馈必须分开。
- 持续格挡允许小步移动；盾牌保护面稳定，身体在后方吸收冲击。
- 盾反包含短预备、快速挥出和恢复；命中时盾牌先停，身体随后回弹。
- 盾面是深色宽面，不使用金色轮廓。

### 单手武器

- 剑、斧、树枝和火把共享握持点与身体挥舞通道。
- 基础挥舞包含预备、有效挥出、接触和恢复四段。
- 武器差异通过长度、重量、恢复时间和 `combo_index` 扩展，不复制整套角色。
- 武器必须由角色姿态系统绘制，关卡不得把独立武器贴在固定手点上。

### 推动大型物体

- 接触前是正常移动；双手接触后进入短暂发力准备。
- 推动循环使用短步，不复用普通跑步。
- 身体前倾，后脚蹬地，前脚短步，手臂近似固定，巨盔轻微滞后。
- 步态相位按照箱子实际位移累计。
- 停止、松手、箱子被卡住或角色失去接触都必须有恢复动作。

## 装备连接约定

### 推拉动作与切换验收（用户明确要求）

- 推箱：角色面向箱子，弯腰前倾，双手撑住箱体，后腿蹬地后交替换步。发力来自身体前压和腿部蹬伸，不能用直立走路加伸手代替。
- 拉箱：角色仍面向箱子，双手抓住木条边缘，身体后仰、重心后移，双腿交替后退，把箱子往自己方向拽。不能用推动动画倒放，也不能转身背对箱子。
- 弯腰、后仰均不能改变原角色的宽短躯干、短四肢和头盔比例；不允许拉长腰部或四肢以迁就姿势。
- 单张姿势图好看不代表动作可用。必须验收现有待机到伸手、抓握、推或拉、停步、反向、松手回待机的连续过程，以及跳跃中断。
- 动作组必须匹配当前角色的显示尺度、固定画布、脚底基准与根节点。禁止按每段或每帧包围盒重新缩放、重新居中；不能切换动作时跳位、变高变矮或突然改变体型。
- 根节点稳定不等于身体僵住：允许连续的屈身、重心移动和抬脚，但接触脚和抓握手不能突然跳到新位置。进入和退出交互需要完整过渡帧，不能从站立硬切到独立生成的拉拽姿势。
- 动画切换不得重设角色或箱子的物理位置。不得用物理瞬移、临时缩放或双帧重影掩盖素材不匹配。
- 未通过造型与连续切换检查的生成图片仅为候选，不得作为合格视频首帧或接入游戏；先确认静态体型，再消费视频生成额度。

- 前后手、肩、腰和背部是统一装备插槽。
- 角色系统负责手臂和装备的最终变换。
- 关卡负责提供装备类型、动作阶段和玩法命中结果。
- 盾牌碰撞框、剑伤害框和箱子碰撞由玩法控制器维护，不由绘制形状反推。

## 验收清单

- [ ] 静止截图中首先识别出歪塔巨盔，其次识别出小骑士身体。
- [ ] 即使压成纯黑，顶部缺口、阶梯前脸和护颊仍具有辨识度。
- [ ] 光效集中在头部，身体没有全身光圈。
- [ ] 走路连续且脚底稳定，没有固定帧硬切和根节点跳动。
- [ ] 任一动作极值都没有缺角、越界裁切、相邻帧残影或抠图毛边。
- [ ] 起步、停止、转身、跳跃顶点和落地都具有不同姿态。
- [ ] 持物移动仍保留步态。
- [ ] 投掷包含蓄力、释放和恢复。
- [ ] 短按盾反与长按举盾视觉上明显不同。
- [ ] 盾牌命中有身体回弹，不只播放火花。
- [ ] 剑类动作可替换武器而不重写角色。
- [ ] 推箱动作由箱子实际位移驱动，停止时自然松手。
- [ ] 原角色资源和 `legacy` 风格仍可使用。
