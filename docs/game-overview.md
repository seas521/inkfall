# 《墨坠 / INKFALL》游戏总纲（v2，2026-10-21 重写，待确认）

> 旧版总纲写的是"黑白线条小魔女"和盾牌/投掷玩法。美术和角色已经换成兜帽男孩加光雾，本文以现在的方向为准。
> 旧关卡设计卡（`docs/levels/`）保留作参考，标有"旧版"，不再作为实现依据。

## 游戏定位

横版氛围解谜平台游戏，向《Limbo》《Inside》这类作品看齐，不追求更长，追求每一段都有一个清楚的点子并发展到底。
- **没有"关卡"的概念**：每个章节对玩家来说就是一整个连续的场景，从头走到尾，不出现关卡名、过关结算、读条或幕布式的切换。章节内部只分若干"记忆点"（一个难忘的画面加一个核心点子），记忆点是我们做设计和排期用的，玩家看不到。

- 玩家控制一个披着兜帽的小男孩，沿着一口"墨坠的井"一路向下，再向前。
- 几乎不用文字。空间、光、雾、声音和角色的肢体动作负责讲述一切。
- 目标体验：安静、压抑、偶尔紧张；死亡不惩罚，重来很快。

## 当前目标

做出**可以对外发布的第一章 demo**：一个连续场景，15 个记忆点，完整约 107 分钟（压缩后目标约 90 分钟；可先发前 8 个记忆点、约 57 分钟的 demo，见 `chapter-01.md`），从头到尾风格统一。具体结构见 `docs/chapters/chapter-01.md`。

## 美术规则（最终风格）

- 画面由**雾、光锥、剪影**构成：近处是纯黑剪影，中景和远景逐层变灰、变虚，用雾和光分层，不靠细节贴图。
- 主体颜色是灰度。**颜色只在玩法上有意义时出现**：
  - 橙色 = 火、光源、目标方向（开场远处的篝火和木屋就是这样的"家"的记号）；
  - 其余不加颜色。水、毒气、岩石目前都是灰度，靠形状、动态和声音表达（建议保持，需要时再讨论是否给毒气一点点颜色）。
- 角色永远是最清晰的剪影；可交互物件靠轮廓和动作暗示，不用图标和文字。
- 同一记忆点的静态环境和动态机关使用同一套光雾，不允许"贴图感"的拼接。
- 角色动作用 Seedance 视频生成，抽帧、插帧后做成帧动画；**动作由玩家输入驱动，动画跟随输入，不能让动画片段卡住操作**。

## 角色（兜帽男孩）

- 外形：小个子，披兜帽，虚弱但倔强；跑得不快，跳得不高（大跳约等于自己的身高），高处要靠攀爬。
- 动作集（已实现）：站立呼吸、走/跑（起步、循环、收步）、起跳（有短暂蓄力，短按小跳）、空中、落地、攀爬（含跳起抓住边缘的过渡）、推/拉箱子、拉船绳、拿风扇并挥扇、受惊刹车、滑落、溺水。
- 还没有的（按记忆点需要再补）：爬绳与摆荡、倒吊、提灯（拿起、点灯、站/走/跑）、挥镐、开锁，以及被巨石碾过、捕兽夹、尖刺的死亡表现。

## 操作

| 键 | 作用 |
|---|---|
| ← → / A D | 移动（站着起步有一小段加速，掉头会快一些） |
| 空格 | 跳；短按小跳，长按大跳；空中靠近边缘会自动抓住攀爬 |
| F | 交互：拾取、放下、拉杆；按住靠近箱子/船，再按方向决定推还是拉 |
| 长按 F 再松开 | 投掷石块（轨迹线只在蓄力时出现） |
| 空中碰到绳子 | 自动抓住；上下键爬，左右键摆，空格松手 |

> 不再有盾牌，不再有"短按盾反/长按举盾"。

## 玩法原则

1. **每个记忆点一两个核心点子**：新点子出现 → 安全地试 → 有风险地用 → 与前面学过的组合，一个记忆点内走完这个循环。
2. **看得见的因果**：机关怎么运作，玩家能从画面看出来；失败后能说出"我哪里错了"。
3. **物件的物理是真的**：箱子能推、船会漂、石头会滚、风能吹动东西；不做"道具图标"式的谜题。
4. **死亡短而轻**：死亡动画 1 秒左右，立刻回到最近检查点（自动记录，有屏幕上轻提示即可）。
5. **输入优先**：控制器的响应不为动画让步，动画去追输入（站着起步时速度和脚步一起涨就是这个原则的例子）。
6. **空间连续**：章节是一整片连续的地形，远景里看到的地方，之后真的能走到，开场望见的景色在结尾回望时对得上。

## 水、光和声音（本章要补齐的氛围层）

- 水面有真实的波动：撞击先压下去再弹起，波向两边传开并慢慢消失，船行驶时有尾波，船会随水晃（已实现）。
- 光雾：光锥、远近分层模糊、粒子尘埃，按记忆点调整浓度。
- **声音目前基本是空白**：环境底噪、脚步（按地面材质区分）、水声、机关、攀爬、落地、死亡，以及每个记忆点一小段配乐（或只在转折处进出），需要在第一章内整体补齐。

## 技术约定

- 引擎：Godot 4.7；章节是场景加脚本（内部按记忆点分段，检查点和机关按段管理），角色通过 `ActorStyleHost` 统一显示，当前固定为兜帽男孩（不再支持 F9 切换）。
- 动作片段、过渡表和状态机的约定见 `docs/art/hood-state-machine.md` 与 `docs/art/hood-integration-plan.md`。
- 测试：每个机制有 headless smoke 脚本；跑 `--script` 的测试需要显式指定角色风格，否则会用旧角色。

## 待确认（会影响后面的设计）

1. **贯穿全章的小线索**：目前草案是"男孩沿着井往下，远处那一点橙色的火和木屋是他要去的地方；沿路都有先他一步走过的人留下的东西，最后在地窖监牢里见到那个人；森林里有捕兽夹、吊索和尖刺坑三种陷阱，陷阱的主人是一个始终看不清的猎人（剪影、灯光、铃声），他是第一章的隐性威胁，是第一章最有特色的一段"，结尾到达的是什么还没定，见 `chapter-01.md` 的草案。
2. 毒气、火之外要不要给水一点点冷色（现在水是灰）。
3. 配乐方向（极简环境音为主，还是有旋律）。
