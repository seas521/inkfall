# 兔子装的动作状态机：评估与方案

## 1. 现状：它其实是一个状态机，但只有一半是显式的

`hood_frame_actor.gd`（686 行）+ `hood_river_actor.gd`（448 行）+ 两个控制器一起在做这件事，分四层，谁写了哪层的状态很分散：

| 层 | 谁决定 | 状态 / 变量 |
| --- | --- | --- |
| 控制器动作层 | 控制器（`pose.action`、`action_progress`） | 击倒、倒地、起身、拾取、放下、投掷、握船 / 推 / 拉 / 绳子、摇杆、溺水、攀爬……约 25 个，进度由控制器的时钟给 |
| 空中层 | 物理（`pose.grounded`、竖直速度） | 起跳 → 上升 → 顶点 → 下落 → 落地，`air_set`（站 / 跑）在起跳时锁定，`land_clip`、`landing_time`、`takeoff_time` 另有计时 |
| 地面移动层 | 速度 + 计时 | `loco`：待机 / 起跑 / 跑 / 刹停 / 喘息 / 起身，外加 `run_total`、`still_time`、`pant_hold`、`pant_time`、`run_hold`、`pending_from` |
| 携带层 | 控制器（`held`、`equipment`） | 抱石头 / 扇子时整套换成 `small_*` 片段 |

问题：
1. **转换没有契约。** 每次状态变化只有两种处理：直接切，或者叫 `_blend_time` 查一张手写的淡入淡出时长表（0–0.6 秒）。切得好不好从来没有量过。`loco` 在 16 处被赋值，空中层和地面层互相改对方的变量（比如攀爬结束要加 `climb_exit` 才不会被当成"落地"），改一处就会碰坏另一处。
2. **转换数量对不上。** 约 45 个状态，任意两个之间都可能发生转换（动作永远不等动画，输入随时打断），约 2000 对；手写处理过的约 20 对。其余走默认的 0.08 秒淡入淡出。
3. **素材没有共同的锚点姿态。** 每段视频都只给了首帧图，结尾姿态是它自己生成的，所以片段的起点和终点都不是"站直待机"或"跑循环"。`scripts/tools/audit_transitions.py` 量了一遍：站立 / 起跑 / 跑 / 刹停 / 喘息（同一段视频）接得上（差异 4–23%）；跳跃、攀爬、直起身和待机 / 跑循环的接缝差异在 50%–160%，身高比最多差 18%。淡入淡出只是把两个不同的轮廓叠起来，所以看着像"变大了""跳帧"。
4. **同一段视频自己的问题。** 直起身那条视频每个姿势占两帧（12 fps 当 24 fps 用），插帧前不去重会卡顿；站直时比待机高 8%，还有先拉长再缩短的过冲。攀爬那条视频里的爬行、弓背起身，不是游戏要的动作。

## 2. 方案：数据驱动的分层状态机，每个转换有成本和处理方式

### 2.1 锚点姿态（"枢纽"）
所有片段的起点和终点都落在少数几个锚点上：

- **A0** 站直待机（`idle_left` 第 0 帧）
- **R0** 跑循环的一个相位
- **P0** 弯腰喘息
- **AIR** 空中是物理驱动的，单独一组，进出口分别在 A0 / R0

控制器动作（拾取、推拉、投掷……）全部从 A0 出发、回到 A0；被打断时按下面的转换表退出。

### 2.2 转换表（离线生成，运行时只查表）
`build_transition_table.py`（扩展现在的 `audit_transitions.py`）对每对用得到的状态 A→B：
1. 在 A 的每一帧到 B 的每一帧之间量轮廓差异（脚底对齐，必要时按身高归一）；
2. 记录最佳帧对和代价，写进清单（现在刹停 / 起跑 `entry_from_run` / `exit_to_run` 就是这个思路的一小部分）；
3. 代价超过阈值（现在建议 12% 差异 / 4% 身高）的转换必须有处理方式：**桥接片段**（首帧给 A 的锚点、尾帧给 B 的锚点生成）、或者**限制**（比如落地过程中不接受再起跳）、或者**允许延迟 N 帧**（只延迟动画，物理一帧都不延迟）。构建时报错，不允许默认淡入淡出蒙混过去。

### 2.3 运行时
- 一个 `enter_state(next, from_frame)`，所有状态变化只走它；变量归各层自己所有，别的层只能发事件。
- 切换流程：查表 → 取最佳帧对 → 代价小：直接切（最多 2–3 帧的淡入，只为遮像素台阶）；代价大：延迟动画最多 100 毫秒到更好的切点，否则播桥接片段。
- 输入和物理永远立即响应，不等动画（这条不变）。

### 2.4 片段制作契约
- 每段视频首帧和尾帧都给图，且是锚点图，体型、脚的位置和锚点图一致；
- 体型在整个视频里不变（审计脚本会量每个片段的站立高度）；
- 抽帧先去重（检测 12 fps 重复帧），再插帧到 60 fps；
- 不要的动作（爬行、弓背、拉伸）在提示词里直接写"没有"。

### 2.5 验证
- `audit_transitions.py` 作为每次打包前的关卡：列出所有转换的差异和身高比，超阈值的不让过。
- 新增"随机输入压测"：脚本里随机按方向 / 跳 / 停 / 攀爬等 N 秒，量每一帧画面和上一帧的轮廓差异（脚底对齐），统计最大值和超过阈值的次数和转换名，当回归指标。这样"跳帧"是一个数，不是看着像不像。
