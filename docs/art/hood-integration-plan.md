# 尖兜帽男孩接入第一关：计划

## 1. 现状（读过代码之后）

- 第一关由两大块组成：
  - **1-01 墨坠井**：`scripts/levels/level_01_controller.gd`，房间依次是 `SURFACE → SHAFT → CAVERN → LEVEL_01_LIFT`。动作：跑、跳、落地、拾取 / 放下 / 投掷石头、受击、击倒、爬起、竖井坠落、落地撞击、趴地、爬起。
  - **C 区**（河流、沼泽、断桥）：`scripts/demos/c_zone_debug/`，场景 `scenes/debug/c_zone_river.tscn`，从 1-01 的 `river_requested` 信号进入，也可以用 DEBUG 菜单直接进第二幕、第三幕。第一幕 `river_controller.gd`（推拉木箱和木筏、取扇、挥扇、落水），第二幕沼泽（瘴气、火焰击飞、惊恐锁定、滚石顶人、落石），第三幕 `cliff_act.gd`（石头、断桥、升降梯）。
- 角色呈现的架构已经很干净：控制器每帧给 `ActorStyleHost.present(delta, state)` 传一个字典（`ActorPoseState`：脚的位置、速度、是否落地、朝向、装备、动作、动作进度、物件、雾模糊、单色等），`style_id` 决定用哪一套角色。现在第一关用的是 `STYLE_CROOKED_TOWER`（`SeedanceFrameActor`，帧动画），C 区在它的基础上扩展出 `river_actor.gd`（抓握、单手持物、挥扇、溺水、脚面贴合）。
- 所以**不需要改玩法逻辑**：新角色是一个新的 style（`STYLE_HOOD`），读同一个 `ActorPoseState`，把状态翻译成片段。我做的测试场景（`hood_clip_lab.gd`）是自己带状态机和物理的原型，不能直接搬进去，要重写成"只读状态、不拥有物理"的角色类。

## 2. 总体做法：新旧角色并存，逐步切换，随时可回退

1. 新增 `STYLE_HOOD` 和 `HoodFrameActor`，加进 `ActorStyleHost`（和 legacy / velvet / shadow / crooked_tower 并列）。
2. 控制器里 `style_id` 现在写死为 `STYLE_CROOKED_TOWER`，改成读一个选项（项目设置或 DEBUG 菜单里一个开关，运行中按键切换），默认先用旧的，新的验收通过再改默认。
3. 旧角色代码和素材整个阶段都保留，全部区域验收完再清理。

## 3. 分阶段：先共用，再逐区

不要"一个区域一个区域地从头接"：移动（跑、跳、落地、停）是每个区域都用的，先做一次就够了。顺序：

## 5. 缺口（第一关要用但还没有）

1. **竖井长坠落循环**：只有一次性翻滚。
2. **击倒（被击飞）**：目前用跌落那一套代替（`fall_air` 的前半），要看起来是否合适。
3. **涉水**：片段做了但循环接缝差，第一关现在没有涉水玩法，可以先不用。
4. **险些掉落的摇摆**：没有做，第一关没有这个玩法，可以以后再说。
5. **大物件**（木头）：第一关没有大物件，素材备用。
6. **抓握点之外的脚面贴合**：C 区现在有一个"脚底贴合斜坡"的小修正（`surface_contact.gd`），新角色的脚没有按斜坡拍摄，先不做脚面贴合，看实机效果再定。

## 6. 风险

- **显存**：见 P0，是最大的工程风险。
- **体型差异**：新角色的帽尖比旧头盔高，动作有大幅度伸展（挥扇、投掷、爬起），要核对不会穿过天花板 / 低矮空间（竖井和矿洞）。
- **帧衔接**：每个衔接都按轮廓匹配过，但第一关里会出现的组合（比如抱着东西从跑变成跳再落地接着推）很多，需要实机逐个看。
- **音频**：脚步声、落地声、拾取声都挂在旧片段的帧或动作事件上，要逐个重新对应。
- **所有现有的冒烟脚本**都按旧片段的名字和帧数断言，需要改成按 style 参数化。

## 7. 验收方式

每个阶段结束都做三件事：两种 style 的冒烟脚本都通过；一组截图（旧 / 新并排）；你在实机里试玩一次这个区域，确认后才进下一个阶段。

2. **起跳没有"发力"**：视频里起跳前有约 0.3 秒的下沉蓄力（第 31–37 帧），游戏里起跳是瞬间的，蓄力的帧被压成 0.125 秒、在身体已经飞起来之后才放。现在改成：按下跳跃后先在地上蓄力 `HOOD_JUMP_WINDUP` 0.09 秒（身体下沉、可以继续移动），然后才离地。起跳片段按蓄力进度播放（`pose.jump_windup`），离地的那一帧直接接上升片段。A/B 区（`PlayerController` + `GameContext.jump_windup_*`）和 C 区（`river_controller`）都接了，只对兔子装生效；要关掉把 `HOOD_JUMP_WINDUP` 改成 0（A/B 区是 `jump_windup_total`）。起跳片段的帧改成视频的蓄力段（跑 31–38 帧），跑中起跳固定从蓄力的第 0 帧开始（不再按最像的帧挑，之前挑到后面的帧会把蓄力跳过去）。
3. **跳起到攀爬的硬切**：抓住台沿时画面从空中的姿势切到攀爬片段的第 0 帧（两段来自不同视频，差异 70%–87%）。做了表（`scripts/tools/build_climb_tables.py`）：对每个空中帧找攀爬"够手"那一段里最像它的帧（落在第 6–12 帧），攀爬从那一帧接着播，位置也从那一帧的脚位过渡；`from_air`、`lead_feet` 写在 `climb` 的 manifest 里。
- 量化探针 `c_zone_debug/hood_transition_probe.gd`：跑向木箱、起跳、抓住、攀爬，量每个物理帧世界坐标里的剪影变化（跑步一步约 2278，起跳 → 上升 4222，上升 → 攀爬 4448，没有超过 3 倍的尖峰）。

### 2026-10-21：起跳到攀爬——补了过渡帧（grab_bridge）和起跳速度
- 量出来的原因（`hood_transition_probe.gd` 现在也量画面中心每帧的移动速度）：抓住的那一帧画面中心一下子跳了 16 px（前一帧还是每帧 3.6 px），攀爬的"够手"姿势和空中姿势来自不同视频，直接切过去就是硬切；另外我之前把物理速度在抓住那一帧清零、位置用"从静止开始的缓动"，也是一个急停。
- 修复一：`scripts/tools/build_grab_bridge.py` 用 RIFE 做过渡帧：对每个空中片段（原地 / 跑动 × 上升 / 顶点 / 下落）每隔一帧，从那一帧到攀爬"够手"里最像它的那一帧（`from_air` 表）生成 6 帧中间画面，最后一帧就是攀爬的那一帧（脚对齐到根点，和别的片段一样以脚为根）。共 198 帧，`climb` 组里的 `grab_bridge`。游戏里抓住台沿后先播这 6 帧（0.1 秒，`pose.grab_frame`），然后攀爬片段从那一帧接着播。

### 2026-10-21：水面波动（C 区第一幕的河）
- 之前：水面只有 0.55 px 的正弦起伏，撞击只有水花和几圈同样大小的环，船动、人涉水时水面毫无反应。
- 现在（`river_art.gd`）：水面是一排 4 px 宽的水柱，按带阻尼的波动方程运动（`WAVE_SPEED 150`、`WAVE_DAMP 1.9`、`WAVE_LEAK 1.3`，约 2.5 s 衰减完，岸边吸收不反弹）。着色器按水柱高度抬/压水面、折射扭曲、水面亮线；`_draw_swell_lines` 画会动的波峰线和两条随波的回声线。
- 触发：`emit_water_impact`（船入水、人跳到船上、人掉进水）= 先压下去，0.17 s 后弹起一个水柱，再回落；溺水挣扎每一划拍一下水；船行驶时船头推起、船尾拉出波谷（`raft_waves`，按船速）；船下沉/摇晃会向外推水；涉水时脚下每步一小拍（`wade_waves`）。
- 反作用：水面高度和坡度会轻微托起、倾斜船（`_update_crate`：升降 0.75 倍、倾角最多 5°），人跟着船走。
- 环：改成 4 圈，越撞得重扩得越远、消失越慢；撞击记录保留到 2.4 s。
- 测试：`water_wave_probe.gd`（波高随时间）、`water_raft_probe.gd`（兜帽男孩在船上）、`water_wave_capture.gd`（窗口截图）。`river_contact_smoke` 的"水花消失"等待从 2 s 改到 2.8 s。
